# 水韵饮水记录 UI 高保真还原设计

## 1. 目标

在现有 HarmonyOS ArkTS 应用中，按参考图完成水韵 AquaFlow 的高保真 UI 还原。验收基准为 HarmonyOS 模拟器 `390 x 844 vp`，优先保证首屏视觉、页面结构、文字层级、交互状态和页面跳转与参考图一致。

本次工作保留现有业务服务、数据模型、持久化和规则测试，不把应用改造成图片展示或不可交互的静态拼图。

## 2. 范围

覆盖参考图中的全部页面和状态：

- 主框架：首页、统计、成就、设置四个底部 Tab。
- 设置流：个人资料、饮水目标、提醒设置、饮品管理、杯具管理、设置页。
- 扩展页：杯具管理扩展状态、植物花园、数据管理、关于水韵弹窗。
- 首页交互状态：快速添加、输入自定义饮水量、选择饮品、记录列表和撤销提示。
- 设置交互状态：保存、返回、主题色切换、深色模式切换、数据备份/恢复/重置和关于弹窗。

首次进入的演示数据必须与参考图对齐：今日饮水 `850 ml`，目标 `2200 ml`，完成率 `38%`，剩余 `1350 ml`；同时提供对应的饮水记录、统计柱状图、成就卡片和向日葵成长数据。用户完成真实操作后，界面显示真实计算结果。

不在范围内：重写现有业务服务、改变数据模型含义、增加服务端能力、制作与参考图无关的新功能。

## 3. 实现方案

采用原生 ArkUI + 自定义绘制的混合方案。

- 页面结构、滚动容器、列表、按钮、表单、弹层和导航使用 ArkUI 原生组件，保证可交互和可维护。
- 环形进度、统计柱状图、饮品构成圆环图、植物视觉和局部装饰使用自定义绘制或专用组件，避免用大量绝对定位拼接页面。
- 抽取共享视觉组件：页面外壳、顶部栏、玻璃卡片、分段控制器、开关、设置行、底部导航、饮水记录行和弹层容器。
- 扩展现有 `Theme.ets`，集中维护颜色、字号、圆角、间距、阴影和状态色；页面不直接散落颜色常量。
- 继续通过现有 `router` 路由进入独立页面，主框架保留四 Tab 状态。

不采用整页背景截图或单一 Canvas 拼图。参考图需要的是可用的饮水应用，且后续记录、主题和设置变化必须能反映到界面。

## 4. 视觉系统

基准画布为 `390 x 844 vp`，内容避开系统安全区。整体使用浅蓝雾化背景和白色卡片层次：

- 页面背景：极浅蓝白，局部使用低对比度蓝色光晕制造参考图的空气感。
- 卡片：白色或半透明白色，圆角约 `24 vp`，细边框和低强度阴影。
- 主色：清透水蓝，主要用于进度、主按钮、选中项和可操作状态。
- 辅助色：植物绿、浅黄、橙红，用于成长、提醒和成就状态，避免全页面只使用蓝色。
- 文字：深海军蓝用于标题和主要数值，灰蓝用于辅助说明；标题、正文、标签和数值建立稳定层级。
- 图标：优先使用现有资源或 ArkUI 可稳定显示的图标/绘制组件；关键视觉不依赖不可控的系统 emoji 字体。
- 底部导航固定高度和选中态，图标、文字和顶部指示色保持参考图的紧凑比例。

## 5. 数据与交互

数据流沿用现有 service/repository 分层。页面加载时读取 `PreferencesService`、饮水记录、饮品、成就、植物和目标数据；首装或空数据状态通过默认演示数据初始化一次。饮水记录成功后刷新首页进度、统计、成就和植物状态，删除/撤销时反向更新这些派生状态。

关键交互契约：

1. 首页快速添加按钮立即创建对应毫升数的饮水记录。
2. 自定义输入弹层支持快捷毫升数、输入校验、取消和确认。
3. 当前饮品入口打开底部饮品选择弹层，选择后回到首页并更新饮品标签。
4. 统计页支持本周、本月、本年分段切换，选中态、图表和摘要卡片保持稳定尺寸。
5. 设置页的每一行都能进入对应页面，保存动作有明确反馈，返回路径不丢失状态。
6. 主题色、深色模式、目标、提醒、饮品、杯具、数据管理和关于弹窗使用现有业务能力；没有实现能力的控件不伪装成可用状态。

## 6. 页面拆分

- `MainPage`：承载底部 Tab 和页面切换状态。
- `HomePage`：顶部日期、环形进度、快速添加、当前饮品、今日记录和弹层。
- `StatsPage`：分段控制器、总量卡、周柱状图、摘要卡、时段分析和饮品构成。
- `AchievementPage`：连续天数、累计饮水、植物成长卡和成就列表。
- `SettingsPage`：个人入口、设置分组、主题色和关于入口。
- `ProfilePage`：头像、昵称、身体信息、活动量、特殊状态和气候环境。
- `GoalSettingsPage`：目标数值、自动计算开关和计算公式说明。
- `ReminderSettingsPage`：提醒开关、间隔、时段、模式和达标后停止。
- `BeveragePage`：饮品列表、含水率、开关和新增入口。
- `CupPage`：杯具新增表单和我的杯具列表。
- `PlantGardenPage`：向日葵主卡、成长阶段和成长提示。
- `DataManagePage`：备份、恢复和重置数据。
- `About`：设置页上的关于水韵弹窗。

## 7. 验证策略

先验证数据和共享组件，再验证页面：

- 运行现有 ArkTS 规则测试，确保目标计算、提醒、饮水和成就规则没有回归。
- 为默认演示数据和 UI 使用的派生数值增加最小单元测试，覆盖 `850/2200`、完成率、剩余量和空数据边界。
- 使用 HarmonyOS 模拟器在 `390 x 844 vp` 下逐页运行，检查首屏和滚动内容。
- 对所有参考图对应状态截图，逐项比较页面外框、留白、字号、卡片高度、进度环、图表、底部导航和弹层位置。
- 手动验证首页添加/撤销、饮品切换、Tab 切换、设置跳转、保存、主题色切换和关于弹窗。

完成标准是：所有范围内页面可进入，核心交互可操作，关键数据显示正确，截图与参考图在指定尺寸下达到视觉高保真，且现有业务测试通过。

## 8. 实施顺序

1. 先统一主题 token、页面外壳和共享组件。
2. 还原主框架、首页、底部导航和首页弹层。
3. 还原统计、成就和设置页。
4. 还原设置流和扩展页。
5. 接通默认演示数据与真实服务刷新。
6. 运行测试、构建应用、逐页截图校验并修正视觉差异。
