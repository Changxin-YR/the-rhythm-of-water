# 元气有数：WaterReminder × JiZhangBen 深度融合设计

日期：2026-08-11  
状态：待用户复核  
目标工程：`WaterReminder`  
最终产品名：`元气有数`  
副标题：`喝水、记账与生活管理`

## 1. 目标与非目标

### 目标

- 将 WaterReminder 与 JiZhangBen 合并为一个最终安装包，功能保持完整。
- 用一个统一概览页同时呈现饮水健康和收支状态。
- 统一两套业务的导航、卡片、按钮、图标语义、间距和浅/深色主题。
- 把重复设置、关于页、数据管理和协议入口收敛到清晰的分组中。
- 保留原有数据服务和业务规则，避免出现第二套写入逻辑。
- 让 API 22 设备上的状态栏、底部安全区、横向布局和深色对比度可验证。
- 继续使用 SDK 22，保持纯单机运行，不新增联网依赖或网络权限。

### 非目标

- 不把饮水记录和账单强行合并成同一张业务表。
- 不删除 WaterReminder 或 JiZhangBen 的核心领域能力。
- 不在没有用户确认的情况下删除旧工程目录或旧数据。
- 不依赖网络服务实现概览、协议、隐私说明或数据迁移。

## 2. 最终产品形态

以 WaterReminder 作为唯一主工程和唯一交付安装包，保留现有包名以便升级兼容，应用展示名称统一为“元气有数”。JiZhangBen 不再作为独立交付包，但其账单、分类、预算、统计、导入导出能力完整进入主工程。

WaterReminder 当前已包含一套 `entry/src/main/ets/ledger` 账本域，且与 JiZhangBen 的账单模型和服务高度同源。实现时以这套已集成域为唯一账本实现，避免复制两套账本逻辑。

## 3. 信息架构

底部一级导航统一为四项：

1. **概览**：日期问候、今日饮水进度、连续达标、本月收支、最近活动、两个快捷操作。
2. **喝水**：饮水记录、饮水目标、提醒设置、饮品管理、植物花园、饮水统计、成就徽章。
3. **账本**：账单列表、记账、账单编辑、分类管理、预算、账本统计。
4. **我的**：头像资料、统一设置、数据与隐私、关于与协议。

原有 StatsPage、AchievementPage、PlantGardenPage、ReminderSettingsPage、LedgerStatisticsPage 等页面继续存在，通过对应业务域的分组入口访问，不再占用一级底部导航。

概览页只读聚合两套服务的摘要。快捷操作分别调用现有 `DrinkService` 和账单域 `BillService`，不新增平行数据写入路径。

## 4. 概览页设计

概览页采用参考图 B 的结构：

- 顶部：问候语、日期、设置入口。
- 今日健康卡：饮水完成量/目标量、百分比、连续达标天数、进度条。
- 本月收支卡：余额、收入、支出、账单数量。
- 快捷操作：`记录饮水`、`记一笔`。
- 最近活动：饮水记录和账单按时间分组展示；没有数据时分别显示空状态。
- 底部：概览、喝水、账本、我的。

饮水和财务摘要必须独立加载、独立失败降级：账单加载失败不能让饮水概览空白，饮水数据异常也不能阻断账本入口。

## 5. 主题与视觉系统

建立共享的语义主题令牌，不允许业务页面直接写死浅色前景或深色背景：

- `canvas/background`：页面背景。
- `surface/card`：卡片、弹层、输入区域。
- `textPrimary/textSecondary/textHint`：主要、次要、提示文字。
- `primary/primaryText`：按钮填充与可读强调文字分离。
- `water`：饮水青色。
- `income`：收入绿色。
- `expense`：支出珊瑚色。
- `divider/progress/inactive`：分割线、进度条、未选中状态。

浅色模式使用低饱和蓝白画布与白色卡片；深色模式使用深蓝黑画布、深蓝卡片和浅色前景。所有主要文字和操作色在浅色、深色下均需达到可读对比度，主题切换后同时刷新系统栏图标、页面背景、卡片和导航。

### 安全区与刷新硬约束

- 页面内容区不侵入系统状态栏和底部导航安全区；安全区只承载与当前主题一致的背景色，不出现白色/黑色断层。
- 沉浸式窗口仍由系统安全区提供尺寸，页面通过统一的顶部/底部 inset 布局；底部可交互控件与导航区保持至少 `28vp` 间距。
- 任何饮水、账单、分类、预算、目标、饮品、植物、成就、提醒、设置、导入、恢复或重置写操作完成后，必须发布统一的单调递增刷新版本号；禁止业务页面直接使用 `Date.now()` 作为刷新信号。
- 概览、喝水、账本、统计、成就和我的页面都订阅同一刷新版本号；收到刷新事件后重新加载自己的服务摘要和主题，不要求切换页面才能看到结果。
- 账本域现有 `DataChangeNotifier` 与应用级刷新信号统一桥接，不能只刷新账本内部列表而遗漏概览或统计。

### 深色模式完整适配

- 深色模式不是只替换页面背景；卡片、输入框、弹层、分割线、按钮填充/文字、选中/未选中态、开关、图表坐标与网格、空状态插图、账本收入/支出状态色、底部导航、状态栏和导航栏都必须使用深色语义令牌。
- 每个页面的交互状态（默认、按下、禁用、选中、错误、成功、空数据、加载中）都要有浅色/深色配色，禁止保留只在浅色可见的硬编码 `Color.White`、浅灰文字或浅色阴影。
- 主题切换完成后，当前页面与已缓存页面同时刷新；系统栏图标明暗、背景和安全区颜色必须与主题同步。

## 7. 数据与迁移

饮水数据、提醒、植物、成就、用户资料和账单数据保持领域隔离；概览只通过服务层读取摘要。

统一备份采用版本化包结构，至少包含：

```text
meta.version
profile
appSettings
reminderConfig
beverages
drinkRecords
plants
achievements
ledger.bills
ledger.categories
ledger.budgets
ledger.metadata
```

WaterReminder 当前数据直接保留。由于 HarmonyOS 应用沙箱按包隔离，JiZhangBen 旧数据库不能被主包静默读取；用户通过 JiZhangBen 原有的按月 CSV 导出文件执行一次性导入。导入适配层负责识别 CSV 表头、日期、收入/支出类型、分类、金额和备注，并将分类名称映射到主工程分类；无法识别的分类进入“其他”并在预览中提示。统一备份仍使用版本化 JSON。两种导入流程都先校验版本/字段并显示将新增、覆盖和跳过的记录数量，用户确认后写入；失败或取消时不修改已有数据。

JiZhangBen 原有的按月 CSV 导出能力继续保留在“账本 > 数据导出”中；统一 JSON 备份用于完整迁移饮水、账本、设置和成就数据，不能替代 CSV 的单月分享场景。

重置数据必须明确展示“饮水数据、账本数据、设置和成就都会清除”，并使用二次确认。

所有成功写入和重置操作都必须在领域写入完成后发布统一刷新版本号；导入/恢复只有在整包校验、写入和提醒重排全部成功后发布一次，任何失败都不得发布部分成功信号。

## 8. 协议与隐私

协议页使用本地静态内容，不要求登录或联网。至少包含：产品用途、数据只保存在本机的说明、提醒能力限制、导入导出行为、重置不可恢复提示、反馈方式和版本信息。协议入口集中在“关于与协议”，不在多个设置页重复出现。
