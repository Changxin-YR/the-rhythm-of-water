# 水韵设置与提醒增强设计

## 目标

本次改动解决四个用户可见问题：

1. 主页面底部四个页面只能通过底部导航点击切换，不允许左右滑动翻页。
2. 个人资料支持选择并持久化一个头像，设置页的个人卡片即时展示。
3. 温柔和积极两种提醒模式产生真实可验证的系统行为差异。
4. 进度环的水滴与黑色方向箭头重叠时隐藏箭头，避免视觉遮挡。

## 已确认的模式语义

- 温柔：按既有时间表发布系统提醒，但 `ringDuration` 为 0、无稍后提醒按钮，不主动响铃。
- 积极：发布闹钟式提醒，保持短响铃、包含“已喝水”关闭按钮，并允许一次稍后提醒。

OpenHarmony 当前 SDK 提供 `ReminderRequestAlarm`，没有独立的普通通知请求类型；因此两种模式共享定时调度结构，使用提醒请求的铃声时长、操作按钮和稍后提醒参数表达差异。保存设置时先取消全部旧提醒，再按当前配置重新发布，关闭开关时只执行取消。

## 组件与数据

### 用户头像

在 `UserProfile` 增加 `avatarId: string`，默认值为内置头像的稳定 ID。头像不使用文件选择器或外部图片权限，采用本地预置头像集合（表情/简单图形）渲染，避免引入不可验证的媒体 URI。`cloneUserProfile`、用户资料 JSON 校验和备份校验都同步处理该字段；读取旧版本数据时缺少字段回退到默认头像。

`ProfilePage` 增加头像预览和“更换头像”入口。点击后使用应用内弹窗/底部面板展示预置头像，选择后仅更新内存中的 profile，点击顶部保存才写入 `PreferencesService`。设置页个人卡片读取 profile 的 `avatarId`，因此返回后刷新信号会同步头像和昵称。

### 页面导航

`MainPage` 直接替换 `Tabs` 为 `Stack` + 条件渲染页面：页面组件由 `currentIndex` 决定，底部导航是唯一切换入口。这样不会继承 `Tabs` 的左右手势翻页能力，也不在页面内部添加横向 `Scroll`；各页面原有的纵向 `Scroll` 保持不变。

### 进度环重叠

`WaterWaveProgress` 继续使用现有 `Gauge` 和水滴文本，新增箭头绘制的条件。根据进度值计算箭头角度和水滴锚点的距离；当两者中心距离小于水滴直径加箭头包围半径的阈值时不渲染箭头。超过阈值仍保持原箭头位置。判定函数放入 `WaterReminderRules` 或独立的纯规则模块，便于单元测试，不依赖 Canvas 或设备尺寸。

## 提醒验证与错误处理

`ReminderService` 抽取纯函数 `buildReminderRequestOptions(mode)`，返回两种模式的铃声、稍后提醒和操作按钮配置；调度流程仍由服务负责调用系统 API。服务记录每次取消、待创建槽位数量、成功/失败数量，并让页面在保存失败时显示错误提示而不立即返回，避免用户误以为设置已经生效。

提醒规则测试覆盖：关闭开关生成 0 个有效请求、时段和间隔生成正确槽位、温柔模式不响铃且不显示稍后按钮、积极模式开启响铃和稍后提醒。设备验证通过设置页保存后重新进入确认持久化，并在提醒设置的短时段内观察系统提醒；若设备权限或系统通知开关阻止发布，页面给出明确提示。

## 测试范围

- `WaterReminderRules.test.ets`：头像旧数据默认值、提醒模式请求选项、箭头重叠边界。
- `ProfilePage`/`PreferencesService`：保存头像后重新读取保持一致；旧 profile JSON 不含头像字段仍可读取。
- `ReminderSettingsPage`/`ReminderService`：保存配置后触发重新调度；关闭时清理旧提醒。
- 构建验证：运行 `hvigorw assembleHap` 或项目可用的等价构建命令。
- 设备回归：底部页面横向滑动不改变页签；底部点击仍能切换；头像选择和保存生效；两种模式分别产生预期提醒行为；进度环重叠时黑色箭头不可见。

## 非目标

- 不增加从相册或相机导入头像。
- 不重做现有页面视觉风格和数据模型之外的功能。
- 不把提醒发送改造成后台定时任务；继续使用系统 Reminder Agent。
