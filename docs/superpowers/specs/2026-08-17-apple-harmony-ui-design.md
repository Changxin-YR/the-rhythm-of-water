# 元气有数 Apple 风格 HarmonyOS UI 设计

## 目标

将现有界面统一为 Apple 式的克制健康风格：内容优先、清晰层级、语义颜色、系统图标、轻量材质和可中断弹性动效。保留 HarmonyOS 原生返回、手势、安全区、深色模式、多窗适配与全部业务数据逻辑。

## 设计方向

采用已确认的 A“克制健康”：浅色优先，使用中性背景和白色内容表面；玻璃材质仅用于底部导航、Sheet 和临时浮层。当前 Apple Liquid Glass 只作为层级表达，不铺满普通卡片。

不复制 SF Pro、SF Symbols 或 iOS 系统控件资源。字体使用 HarmonyOS Sans，图标优先使用 ArkUI `SymbolGlyph` 或项目自有矢量资源，视觉比例和层级参照 Apple HIG。

## 规则优先级

1. Huawei UX 强制要求与 ArkUI 原生行为。
2. 无障碍、数据安全、系统手势和多设备适配。
3. Apple HIG 的清晰、克制、层次与连续动效。
4. 元气有数的健康与记账语义。

## 视觉系统

- 颜色：动作蓝、饮水青、成功绿、记账橙和危险红只表达语义；普通文字、背景和分隔线保持中性。颜色全部通过主题 token 访问，覆盖浅色和深色。
- 排版：页面大标题 26-28fp，页面标题 22fp，分区标题 17-18fp，正文 15-17fp，辅助文字 12-14fp。减少粗体数量，金额和饮水量使用等宽数字特性可用时启用。
- 布局：4vp 微调、8vp 常用节奏，页面水平边距 20vp；普通内容表面圆角 14-16vp，浮层 20vp。删除重复边框、重阴影和装饰性模糊光斑。
- 触控：项目标准 48vp，任何命中区不得小于 Huawei 强制下限 40vp。
- 图标：生产界面不直接显示 Emoji。已有 Emoji 数据值继续兼容，由渲染层映射到系统符号或矢量资源。

## 组件与页面

- 主题：收敛 `Theme.ets` 与 `LedgerTheme.ets` 的色彩差异，共享同一语义色结果；不改账本存储结构。
- 背景与卡片：`AppBackground` 移除装饰光斑；`GlassCard` 改为轻表面组件，不再默认边框和发光阴影。
- 导航：四标签继续使用当前信息架构，统一 `SymbolGlyph`；选中态用颜色和轻微形变，底栏与系统导航区连成一个材质层。
- 标题栏：返回、添加和设置使用熟悉符号，命中区 48vp；子页面保持系统 Back。
- 概览：饮水和收支成为两块主摘要，去掉“卡片套卡片”；快捷操作降低视觉权重。
- 喝水：保留圆形进度、快捷杯量、饮品切换和记录列表；删除水滴 Emoji，突出数值和进度。
- 账本：减少大面积紫蓝填充与超大圆角，用中性表面承载数据，收入/支出只保留语义色。
- 我的及子页面：设置项采用分组列表，表单、弹窗、空状态和危险操作统一组件状态。

## 动效

- 点击反馈：约 120-160ms，缩放不低于 0.97；释放使用轻弹性回归。
- 标签切换：200-260ms 的淡入与轻位移，不做整屏夸张滑动。
- 父子页面：沿用 HarmonyOS 层级转场；创建类流程从底部进入，编辑类流程使用淡入。
- 记录详情和统计继续使用系统路由转场，本轮不增加自定义共享元素转场。
- 不添加循环装饰动画，也不新增项目级动效设置。

## 数据与错误状态

不修改服务、仓储、数据库、备份格式或路由契约。加载失败、空数据、删除确认和撤销继续使用现有逻辑，只统一视觉表现；错误状态必须保留文字说明，不能只靠颜色。

## 技能

创建全局 `harmonyos-apple-ui` 技能，保持精简：一个 `SKILL.md`、Apple/Harmony 设计规则参考和 ArkUI 验收清单。技能不复制完整第三方仓库，不增加运行时依赖，也不重复项目已有验证脚本。

## 验收

- 静态扫描确认生产 UI 不再直接显示 Emoji，用户自定义内容兼容除外。
- 现有 PowerShell UI/合规检查、Hypium 和 release 构建通过。
- 手机模拟器验证四个主标签、代表子页面、弹窗、浅色和深色。
- 截图检查文字无裁切、控件无重叠、状态栏和底部系统区清晰。
- 动效用录屏或帧级证据验证；无法运行的平板、横屏、多窗状态标记为 `unverified`，不虚报通过。

## 非目标

不修改业务功能、产品信息架构、数据库、备份格式、应用图标和上架资料；不引入 SwiftUI、Web UI、第三方图标库或自定义动画框架。
