# 补水啦账本整合与上架整改设计

## 目标

将 `C:\Users\27363\Desktop\APP\JiZhangBen` 的随机账本功能整合进补水啦，使用户在一个 HarmonyOS 应用中完成补水管理和本地收支记录；同时修复审核指出的底部导航避让、颜色对比度和提醒成功提示不真实的问题。

应用继续使用补水啦的包名、签名和首个入口。账本首次使用时从空数据开始，仅创建默认收支分类，不迁移随机账本或其他应用的历史数据。

## 范围

包含：

- 在补水啦主导航增加第五项“账本”。
- 整合账单新增、编辑、删除、检索和收支筛选。
- 整合分类管理、月预算、收支统计、连续记账、CSV 导出和账本数据清除。
- 将账本的 RDB、服务、模型、公共工具、组件、页面和必要资源迁入补水啦。
- 为沉浸式页面的所有底部交互控件保留不少于 28vp 的系统导航避让。
- 校正补水和账本界面的文字及状态色对比度。
- 仅在提醒代理实际发布完成时报告提醒成功，并针对未开通能力给出准确反馈。

不包含：

- 账本云同步、登录、网络接口或第三方 SDK。
- 对既有补水记录、用户设置或备份格式的迁移。
- 对既有随机账本安装包数据的导入。
- 修改签名、包名、证书或 AppGallery Connect 的后台配置。

## 导航与页面

`MainPage` 维持单一主底部导航，顺序为“补水、补水统计、账本、成就、设置”。账本占用一个主入口，不新增第二个固定底部栏。

账本主页面复用随机账本的首页、账单、统计和管理内容，但将原来的账本底栏改为顶部切换。账单新增、编辑、预算、分类管理和详细统计仍使用独立路由页面。这样主底栏始终只有一层，账本功能仍可完整访问。

## 模块与数据

随机账本代码迁入 `entry/src/main/ets/ledger/`，在其中保留 `common`、`components`、`models`、`pages` 和 `services` 边界。页面、模型、服务和公共类都以 `Ledger` 前缀或目录边界与补水模块区分，避免 `Constants`、`DateUtils`、`StatisticsPage` 等同名符号冲突。

账本数据库在应用 `EntryAbility` 启动时初始化一次。数据库使用独立名称和账本表：账单、分类、预算、连续记账状态与元数据。初始化只写入内置分类和空的连续记账状态，不读取旧 `Preferences`，因此首次显示为空账本。

账本资源以 `ledger_` 前缀保留在当前模块资源中。只有账本页面实际引用的字符串、颜色、SVG 和图片会迁入，现有补水图标和资源不替换。

## 上架整改

### 底部导航条

应用继续采用沉浸式系统栏，但 `SystemBarService` 同时发布顶部和底部安全区高度。底部导航、账本的底部输入或操作区，以及有固定底部按钮的页面，统一使用 `max(系统底部安全区, 28vp)` 作为底部避让。背景可延伸到系统区域，文本、图标和可点击控件不能进入该区域。

账本从独立应用迁入后不再维护自己的窗口避让状态；它使用补水啦统一的安全区状态，避免两套状态竞争。

### 颜色对比度

主题 token 和账本资源中的正文、辅助文字、禁用文字、选中态文字、成功、警告和错误色将以各自实际背景进行审计。正文和交互标签满足最小 4.5:1 对比度；大号文本和纯装饰色不被当作正文颜色使用。页面不再为可读文字直接使用浅主题色。

### 代理提醒

保存提醒的顺序保持为：保存配置、清理旧提醒、检查通知与权限、生成时间点、发布系统代理提醒。只有全部请求的提醒都发布成功，才显示“提醒已保存并生效”并返回上一页。

通知未启用、权限未授予、设备配额不足、代理提醒能力未开通和发布失败分别显示不同结果；失败时配置已经保存但页面保持打开。`1700002` 且尚未发布任何提醒时视为未开通代理提醒能力，而非保存成功。

`ohos.permission.PUBLISH_AGENT_REMINDER` 的声明不能替代 AppGallery Connect 能力授权。发布前必须在 AppGallery Connect 申请代理提醒能力、下载包含该能力的新签名 Profile，并用新 Profile 构建和安装 HAP。

## 验收

1. 补水啦从主导航可进入完整账本，账本没有数据迁移且首次只显示默认分类。
2. 账本可新增、编辑、删除、搜索与筛选账单；可管理分类、设置预算、查看统计、导出 CSV 和清除账单数据。
3. 所有沉浸式底部交互控件与系统导航区域之间有至少 28vp 避让，包含账本和补水主导航。
4. 浅色与深色主题的正文、辅助文字和状态文案达到对应背景的最小对比度要求。
5. 没有代理提醒能力时，保存提醒不会显示为已生效；能力开通后，真机可创建并观察系统提醒。
6. ArkTS 规则测试、release 构建和 API 22 设备安装均通过。
