# 元气有数界面修复与用户协议设计

## 目标

修复截图中无法进入的页面、账本弹窗文字不可读、预算图表中心字体过小和协议页顶部被状态栏遮挡的问题；用户协议只描述“元气有数”当前具备的功能。

## 范围与根因

- `main_pages.json` 未登记 `StatsPage`、`AchievementPage` 和 `SettingsPage`，但页面已有点击事件，因此路由无法解析。
- 账本的分类和预算输入框未设置前景及占位文字颜色，平台默认颜色在深色页面上不可读。
- 预算圆环 Canvas 使用过小的像素字号，中心百分比和说明文字与周围界面不成比例。
- 协议页未使用顶部安全区；旧文案把产品介绍、隐私和历史账本导入说明拼在一起。

## 设计

1. 在页面清单中登记已存在的三个页面，保留现有点击和路由路径。
2. 在账本语义色中复用 `ledger_ink` 与 `ledger_text_secondary`，为预算和分类输入框明确设置输入及占位文字颜色；不创建新的主题系统。
3. 仅调整预算 Canvas 的两处字体大小，使百分比可与主要按钮文字同级阅读。
4. 将协议页标题改为“用户协议”，顶部采用 `safeAreaTop`，返回控件提供 44vp 点击区；重写正文为服务内容、本地数据、提醒、账本与预算、使用规范、免责及协议变更七节。

## 验收

- 统计、成就与设置路径都出现在页面清单中。
- 两个账本输入框都有明确的输入和占位颜色。
- 预算中心文案不再使用原有小字号。
- 协议标题和正文只描述本应用功能，且顶部安全区变量存在。
- 运行静态修复契约、现有审核检查、Hypium 测试与 release 构建。
